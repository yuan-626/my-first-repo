📜 核心概念 · Core Concept

大模型的上下文 (LLM Context)

大模型在一次对话中所能"看到"的所有信息——决定了它知不知道、能记得你说过什么。

📌 一句话理解

上下文 = 大模型在生成下一个字时所能"看到"的全部输入内容，包括 系统提示、对话历史、用户当前问题、工具返回结果、外部检索片段 等。超出上下文窗口的内容，模型就"看不见、记不住"。

📦 上下文的组成部分

🧭

系统提示 (System Prompt)

设定模型身份、行为准则、工具使用规范等"前置指令"。

💬

对话历史 (Messages)

用户与助手此前的多轮问答，按时间顺序排列。

🧰

工具结果 (Tool Outputs)

Agent 调用工具后的返回值，会被注入下一轮对话。

📚

检索片段 (RAG Context)

从外部知识库检索得到的相关文本，临时塞进提示里。

📏 上下文窗口有多大？

GPT-3.5 (2022)~4K tokens
GPT-4 (2023)8K / 32K
Claude 3.5 (2024)200K
Gemini 1.5 Pro (2024)1M / 2M

💡 1 个中文字 ≈ 1.5 ~ 2 个 tokens；上下文越长，处理成本越高、响应越慢。

⚠️ 上下文的三大陷阱

1. 中间遗忘 (Lost in the Middle)

超长上下文中，模型对中间段的引用最不准，首尾反而记得清。

2. 上下文污染

RAG 检索塞进了错误片段，模型反而一本正经地胡说。

3. Token 成本暴涨

百万级上下文每次调用费用可能上百元，需谨慎设计。

🧪 上下文示例

[System]
你是一位耐心的编程老师，回答用中文，举例清楚。

[User 第1轮]
什么是闭包？

[Assistant 第1轮]
闭包是指函数可以"记住"创建时的变量……

[User 第2轮]
能用 Python 举个例子吗？

💡 第 2 轮时，模型收到的"上下文"是 [System] + [User1] + [Assistant1] + [User2] 这四段拼起来。
